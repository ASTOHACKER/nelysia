These are v0.5.0 feature-set release-candidate evidence runs from the current
v0.5.1 workspace, not a 24-hour production-readiness claim.

Environment: AMD Ryzen 5 5600 (6 cores / 12 threads), Linux, Node.js v26.8.2.
The runner uses a static `/health` route with request IDs enabled and a 200-route
dynamic table (`/uN/:id`) with request IDs disabled. Each request is executed
through `app.handle`; both route classes are alternated.

| Gate | Requests | Elapsed | Throughput | Failures | Runtime errors | Heap delta | RSS delta |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| `npm run soak:1m` | 1,000,000 | 3.96 s | 252,479 req/s | 0 | 0 | +6.21 MiB | +30.81 MiB |
| `npm run soak:10m` | 10,000,000 | 39.22 s | 254,955 req/s | 0 | 0 | +17.98 MiB | +49.99 MiB |

Both processes exited successfully. The 10M samples show allocator/runtime RSS
steps followed by a stable plateau around 146 MiB; this is reported separately
from heap behavior and is not treated as an automatic failure. The runner emits
periodic samples so a future release-candidate run can compare continuing growth
over the same route mix.
