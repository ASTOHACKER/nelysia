Nelysia is a compiler-first TypeScript backend framework. Build with an ergonomic, chainable API, then run a server specialized around the routes, schemas, and runtime you actually use.

Nelysia คือ TypeScript Backend Framework สายพันธุ์ใหม่ที่ออกแบบด้วยแนวคิด Compiler-First เขียนโค้ดได้อย่างคล่องตัวด้วย Chainable API แล้วคอมไพล์ออกมาเป็นเซิร์ฟเวอร์ที่ปรับแต่งตาม Route, Schema และ Runtime ที่คุณใช้งานจริงแบบ Zero-overhead

Core Philosophy & Architecture สถาปัตยกรรมและปรัชญาการออกแบบ

Traditional web frameworks route all HTTP traffic through a universal, generic pipeline where every request allocates context objects, parses query parameters, resolves headers, and iterates through middleware arrays. Nelysia breaks this paradigm by introducing ahead-of-time (AOT) static route analysis.

เว็บเฟรมเวิร์กทั่วไปมักส่งทุก Request วิ่งผ่าน Pipeline รูปแบบเดียวกันหมด ซึ่งต้องจองหน่วยความจำสำหรับ Context Object, Parse ข้อมูล Query และวนลูปผ่าน Middleware เสมอ Nelysia ปฏิวัติการทำงานนี้ด้วยการใช้ระบบวิเคราะห์ Route ล่วงหน้า (AOT Static Route Analysis)

COMPILED PATH

Static routes with constant values bypass context allocation and run directly at maximum possible throughput.

เส้นทางที่เป็นค่าคงที่ (Static Value) จะข้ามขั้นตอนการสร้าง Context ทั้งหมด ตอบสนองได้ด้วยความเร็วสูงสุดระดับเนทีฟ

SPECIALIZED PATH

Routes with dynamic URL parameters extract only necessary segment values without paying for unused cookie or query parsing.

เส้นทางที่มี Parameter ใน URL จะดึงเฉพาะค่าที่จำเป็น ตัด overhead จากการอ่าน Cookie หรือ Query ที่ไม่ได้ใช้ออกไป

GENERIC PATH

Dynamic routes with hooks, schemas, or opaque handlers safely retain full context, error handling, and lifecycle guarantees.

เส้นทางที่มี Hooks ซับซ้อน หรือ Schema หลายระดับ จะทำงานบน Full Pipeline ที่ปลอดภัยและยืดหยุ่นเต็มรูปแบบ

Quick Start เริ่มต้นใช้งานอย่างรวดเร็ว

Export app from its own module so the compiler and CLI can inspect and build the route graph without prematurely binding to an HTTP port.

ควร export const app แยกไว้เสมอ เพื่อให้ตัววิเคราะห์คอมไพเลอร์และ CLI สามารถอ่าน Route Graph ได้โดยไม่ต้องเปิด Port ค้างไว้ระหว่างขั้นตอนการ Build

src/app.ts
import { Nelysia } from "@narudom96/nelysia"

export const app = new Nelysia()
  .get("/", "Hello from Nelysia!")
  .get("/users/:id", ({ params }) => ({
    id: params.id,
    timestamp: Date.now()
  }))

if (import.meta.main || process.env.NODE_ENV !== "test") {
  app.listen(3000)
}

node --experimental-strip-types src/app.ts

# Or run with Bun
bun run src/app.ts

Nelysia Instance & Options การสร้าง Instance และการตั้งค่า

Configure security, body limits, proxy trust, and global telemetry during initialization:

กำหนดค่าความปลอดภัย, ขนาดสูงสุดของ Request Body, การทำงานร่วมกับ Reverse Proxy และ Telemetry:

Options Configuration
import { Nelysia } from "@narudom96/nelysia"

const app = new Nelysia({
  // Max body payload in bytes (default: 1MB = 1048576)
  bodyLimit: 5 * 1024 * 1024, // 5 MB

  // Resolve clientIp from X-Forwarded-For if behind trusted load balancers
  trustedProxy: true,

  // Enforce Secure flag on all outgoing cookies automatically
  secureCookies: true,

  // Skip request-ID generation + x-request-id header (default: true)
  requestId: false,

  // Global telemetry hooks
  telemetry: {
    onRequest(ctx) { console.log(`Incoming: \${ctx.request.method} \${ctx.request.url}`) },
    onResponse(ctx, res) { console.log(`Status: \${res.status}`) },
    onError(ctx, err) { console.error(`Error:`, err) }
  }
})

Routing & HTTP Methods ระบบ Routing และ HTTP Methods

Nelysia features deterministic route matching. Static paths execute via direct $O(1)$ dictionary lookups. Parameter routes extract path variables. If an existing path receives an unsupported method, Nelysia returns 405 Method Not Allowed with the Allow header populated automatically. OPTIONS and HEAD requests are resolved out of the box.

ระบบ Route ของ Nelysia ทำงานอย่างแม่นยำ เส้นทาง Static ค้นหาผ่าน Hash Table ด้วยความเร็ว $O(1)$ เส้นทางที่มีพารามิเตอร์จะถูกจับคู่อย่างถูกต้อง หากมีการเรียก Method ที่ไม่ได้เปิดไว้ จะตอบกลับด้วย 405 Method Not Allowed พร้อม Header Allow อัตโนมัติ รวมถึงรองรับ OPTIONS และ HEAD ในตัว

Route Registration
// Method chaining
app
  .get("/items", () => [{ id: 1, name: "Widget" }])
  .post("/items", ({ body }) => ({ created: true, body }))
  .put("/items/:id", ({ params, body }) => ({ id: params.id, updated: body }))
  .delete("/items/:id", ({ params }) => ({ id: params.id, deleted: true }))
  .patch("/items/:id", ({ params, body }) => ({ id: params.id, patch: body }))
  .getStatic("/health", { status: "ok" }) // 100% Context-free compiled route
  .all("/api/auth/*", async (ctx) => auth.handler(new Request(ctx.request.url, {
    method: ctx.request.method, headers: ctx.request.headers
  }))) // every HTTP method

A path ending in /* is a wildcard route: it captures every sub-path beneath its prefix, exposed as params["*"]. Wildcards must be the final segment and are always served through the generic runtime.

Path ที่ลงท้ายด้วย /* คือ wildcard route จับทุกเส้นทางย่อยภายใต้ prefix นั้น ค่าที่เหลืออยู่ใน params["*"] ต้องอยู่ตำแหน่งสุดท้ายของ path เท่านั้น และจะทำงานบน generic runtime เสมอ

Wildcard Route
app.get("/files/*", ({ params }) => ({ rest: params["*"] }))
// GET /files/a/b.txt → { "rest": "a/b.txt" }

Path rules: every path must start with /. Parameter names must match ^[A-Za-z_][A-Za-z0-9_]*$. A trailing slash (/users/) matches the same route as /users. Registering the same method + path twice throws Duplicate route. Non-function values passed to .get(path, value) become precompiled static routes (context-free, standalone-eligible) — the fastest tier.

กฎของ path: ทุก path ต้องขึ้นต้นด้วย / ชื่อ parameter ต้องตรง ^[A-Za-z_][A-Za-z0-9_]*$ ลงท้ายด้วย slash (/users/) ถือเป็น route เดียวกับ /users ลงทะเบียน method + path ซ้ำจะ throw Duplicate route การส่งค่าตรงๆ (ไม่ใช่ function) ให้ .get(path, value) จะกลายเป็น static route ที่ precompile ไว้ — เร็วที่สุด

HEAD & OPTIONS: HEAD reuses the matching GET route and returns headers with an empty body. OPTIONS on an existing path returns 204 with an Allow header listing GET, HEAD, OPTIONS, ….

HEAD & OPTIONS: HEAD ใช้ route GET ที่ตรงกันและตอบ header กลับโดยไม่มี body ส่วน OPTIONS บน path ที่มีอยู่จะตอบ 204 พร้อม header Allow เช่น GET, HEAD, OPTIONS, …

Status When
400 Unsupported HTTP method Method outside GET/POST/PUT/PATCH/DELETE/OPTIONS/HEAD.Method นอกเหนือจาก GET/POST/PUT/PATCH/DELETE/OPTIONS/HEAD
400 Malformed JSON body Body claims application/json but does not parse.Body ระบุ application/json แต่ parse ไม่ผ่าน
400 validationvalidation Any t.* / Standard Schema check fails (handler never runs).Schema ใดๆ ไม่ผ่าน (handler จะไม่ถูกเรียก)
413 Request body is too large Payload exceeds bodyLimit (default 1 MB).ขนาดเกิน bodyLimit (ค่าเริ่มต้น 1 MB)
404 Not Found No route matches the path.ไม่มี route ตรงกับ path
405 + Allow Path exists but method is not registered.path มีอยู่แต่ไม่ได้ลงทะเบียน method นี้
429 + Retry-After Only from the rateLimit plugin when the window budget is exhausted.จากปลั๊กอิน rateLimit เมื่อใช้โควตาหมดเท่านั้น

Each handler receives an isolated, request-scoped Context object with all parameters and utilities:

แต่ละ Route Handler จะได้รับ Object Context ที่ถูกสร้างแยกตาม Request มีฟิลด์และเมธอดดังนี้:

Request ID precedence: request.requestId (set by HTTP adapters as a UUID per request) → incoming x-request-id header → deterministic fallback req-METHOD-URL. Every response carries the resolved ID in its x-request-id header, and telemetry spans include it for tracing. Set requestId: false to skip generation entirely (Elysia-like fast path, recommended for benchmarks).

ลำดับ Request ID: request.requestId (adapter สร้าง UUID ต่อ request) → header x-request-id ที่ client ส่งมา → fallback req-METHOD-URL ทุก response จะมี header x-request-id และ span ของ telemetry จะมี ID นี้เพื่อตาม trace ตั้ง requestId: false เพื่อข้ามการสร้าง ID ทั้งหมด (เร็วแบบ Elysia แนะนำสำหรับ benchmark)

Client IP: clientIp reads the first entry of X-Forwarded-For only when trustedProxy: true; otherwise it uses the socket remoteAddress (often undefined on edge runtimes). The rateLimit plugin keys on clientIp ?? "anonymous" by default — leave trustedProxy: false unless you control the proxy, or clients can spoof the key.

Client IP: clientIp อ่านค่าแรกของ X-Forwarded-For เฉพาะเมื่อ trustedProxy: true มิฉะนั้นใช้ remoteAddress ของ socket (บน edge มักเป็น undefined) ปลั๊กอิน rateLimit ใช้ clientIp ?? "anonymous" เป็น key ค่าเริ่มต้น — อย่าเปิด trustedProxy หากไม่ได้คุม proxy เอง เพราะ client ปลอม key ได้

app.get("/session", ({ cookies, setCookie }) => {

Responses & Streaming การตอบกลับ (Responses) และ Streaming

Handlers can return plain JavaScript objects, strings, numbers, custom responses using context.response(), native Web Standard Response, or ReadableStream for real-time streaming:

Handler สามารถส่งผลลัพธ์กลับได้หลายรูปแบบ: Object/Primitive ทั่วไป, ฟังก์ชัน context.response(), อ็อบเจกต์ Response ดั้งเดิม หรือ ReadableStream สำหรับการส่งข้อมูลแบบต่อเนื่อง (Streaming):

Streaming and Response Types
// 1. Custom status and headers
app.post("/create", ({ response }) => {
  return response(201, { created: true }, { "x-custom": "@narudom96/nelysia" })
})

// 2. Chunked streaming via ReadableStream
app.get("/stream", () => {
  const stream = new ReadableStream({
    start(controller) {
      controller.enqueue(new TextEncoder().encode("Data chunk 1\n"))
      controller.enqueue(new TextEncoder().encode("Data chunk 2\n"))
      controller.close()
    }
  })
  return new Response(stream, {
    headers: { "content-type": "text/plain; charset=utf-8" }
  })
})

Schema Validation & Type Safety การตรวจสอบ Schema และ Type Safety

Nelysia provides a lightweight, zero-dependency schema builder t, and natively adheres to the Standard Schema (v1) specification—allowing direct interoperability with Zod, Valibot, and ArkType.

Nelysia มีตัวสร้าง Schema น้ำหนักเบาในตัวคือ t และรองรับมาตรฐาน Standard Schema (v1) โดยสมบูรณ์ จึงใช้งานร่วมกับ Zod, Valibot หรือ ArkType ได้ทันที

Built-in schema (t) & Zod
import { Nelysia, t } from "@narudom96/nelysia"
import { z } from "zod"

const app = new Nelysia()
  // Built-in 't' schema
  .post("/users", ({ body }) => body, {
    body: t.Object({
      name: t.String(),
      age: t.Number()
    })
  })
  // Standard Schema with Zod
  .post("/articles", ({ body }) => body, {
    body: z.object({
      title: z.string().min(3),
      published: z.boolean()
    })
  })

Validate five points of a request at once — params, query, headers, body, plus the outgoing response:

ตรวจสอบได้พร้อมกัน 5 จุด — params, query, headers, body และขาออก response:

Five Validation Points
app.post("/articles/:id", ({ params, query, body }) => ({ params, query, body }), {
  params: t.Object({ id: t.String() }),
  query: t.Object({ draft: t.String() }),
  headers: t.Object({ authorization: t.String() }),
  body: t.Object({ content: t.String() }),
  response: t.Object({ content: t.String() })
})
Builder Accepts Rejects (→ 400)
t.String() typeof v === "string" anything elseอย่างอื่นทั้งหมด
t.Number() finite numbers (NaN/Infinity rejected)ตัวเลข finite (NaN/Infinity ไม่ผ่าน) strings, NaN, Infinitystring, NaN, Infinity
t.Boolean() true | false truthy strings like "true"string อย่าง "true"
t.Object({…}) plain objects; every key in the shape is required, validated recursively as path.keyobject ธรรมดา ทุก key จำเป็น ตรวจ recursive เป็น path.key null, arrays, missing keysnull, array, key ขาด

That is the entire built-in builder — there is no t.Array, t.Optional, or t.Literal. For anything richer, use a Standard Schema library (Zod/Valibot/ArkType) or compose t.Object. Derive static types with Infer<typeof UserSchema>, and adapt any Standard Schema manually with fromStandardSchema(schema).

นี่คือ builder ในตัว ทั้งหมด — ไม่มี t.Array, t.Optional หรือ t.Literal ถ้าต้องการมากกว่านี้ให้ใช้ Standard Schema (Zod/Valibot/ArkType) หรือประกอบ t.Object เอา ดึง static type ด้วย Infer<typeof UserSchema> และ adapt schema เองด้วย fromStandardSchema(schema)

Failure Contract Validation runs before handler execution. Invalid schemas immediately return 400 Bad Request with exact issue diagnostics. Request bodies exceeding bodyLimit return 413 Payload Too Large. การตรวจสอบจะทำงานก่อนที่ Handler จะถูกเรียกเสมอ หากข้อมูลไม่ถูกต้องจะตอบกลับด้วย 400 Bad Request ทันที และหากขนาด Body เกินกว่า bodyLimit จะตอบกลับด้วย 413 Payload Too Large

Lifecycle Hooks & Error Handling Lifecycle Hooks และการจัดการข้อผิดพลาด

Hooks are strictly ordered. Returning a response from onBeforeHandle stops the pipeline immediately (ideal for authentication guards).

Hooks ทำงานเรียงตามลำดับอย่างแม่นยำ หากใน onBeforeHandle มีการส่ง Response กลับ ระบบจะหยุดประมวลผลทันที (เหมาะสำหรับระบบ Auth Guard)

Lifecycle Pipeline
import { Nelysia, HttpError } from "@narudom96/nelysia"

const app = new Nelysia()
  // 1. Before hook: Authorization Guard
  .onBeforeHandle(({ headers, response }) => {
    if (!headers.has("authorization")) {
      return response(401, { error: "Missing authorization header" })
    }
  })

  // 2. After hook: Response inspection or decoration
  .onAfterHandle((context, result) => {
    result.headers.set("x-served-by", "Nelysia")
  })

  // 3. Centralized error handling
  .onError((error, context) => {
    if (error instanceof HttpError) {
      return context.response(error.status, { error: error.message })
    }
    return context.response(500, { error: "Internal server error" })
  })

Graceful Server Shutdown การปิดเซิร์ฟเวอร์อย่างปลอดภัย (Graceful Shutdown)

Drain active requests and close idle connections safely on SIGINT or SIGTERM:

ระบายคำขอที่กำลังทำงานและปิด Connection ที่ค้างอยู่เมื่อได้รับสัญญาณ SIGINT หรือ SIGTERM:

Graceful Shutdown
import { gracefulShutdown } from "@narudom96/nelysia"

const server = app.listen(3000)

process.on("SIGTERM", async () => {
  await gracefulShutdown(server, 5000) // 5s timeout
  process.exit(0)
})

Plugin System & Built-in Plugins ระบบปลั๊กอินและปลั๊กอินในตัว

Nelysia has two composition primitives: use(fn) runs a setup function against the app (the only plugin shape — there is no instance-as-plugin, no decorate/state, no guard/group), and mount(prefix, subApp) grafts another app's routes under a path prefix. Hooks registered on the parent before or after mounting always apply to its own routes; a mounted child's routes keep the child's own before/after/error lifecycle and never leak into sibling routes.

Nelysia มีกลไกประกอบร่าง 2 แบบ: use(fn) รันฟังก์ชัน setup กับแอป (เป็น plugin รูปแบบเดียว — ไม่มี instance-as-plugin, ไม่มี decorate/state, ไม่มี guard/group) และ mount(prefix, subApp) ย้าย route ของแอปลูกมาอยู่ใต้ prefix Hook ของ parent ไม่ว่าจะลงทะเบียนก่อนหรือหลัง mount มีผลกับ route ของตัวเองเสมอ ส่วน route ที่ mount มาจะเก็บ lifecycle before/after/error ของลูกไว้ ไม่รั่วไป route ข้างเคียง

AI SDK Integration การเชื่อมต่อ AI SDK

import { generateText, type LanguageModel } from "ai"
import { Nelysia } from "@narudom96/nelysia"

export function createAiSdkApp(model: LanguageModel): Nelysia {
  return new Nelysia().post("/ai", async ({ body, response }) => {
    if (!body || typeof body !== "object" || typeof (body as any).prompt !== "string") {
      return response(400, { error: "Expected a JSON body with a string prompt" })
    }
    const { text } = await generateText({ model, prompt: (body as any).prompt })
    return { text }
  })
}

Full-Stack Framework Integrations การใช้งานร่วมกับ Full-Stack Frameworks

Use Nelysia as your unified backend engine across modern web frameworks via createFetchHandler:

ใช้งาน Nelysia เป็น Backend API ใน Frameworks ยอดนิยมผ่านฟังก์ชัน createFetchHandler:

NEXT.JS (APP ROUTER)

app/api/[[...slug]]/route.ts
Export GET, POST, PUT, DELETE wrapping the fetch handler.

NUXT

server/api/[...].ts
defineEventHandler(e => handler(toWebRequest(e)))

SVELTEKIT

src/routes/api/nelysia/+server.ts
Destructure request from the RequestEvent.

ASTRO

src/pages/api/nelysia.ts
Export the fetch handler as endpoint methods directly.

TANSTACK START

src/routes/api/nelysia.ts
Export the Fetch boundary for server routes.

Framework Wiring
// Next.js App Router — app/api/[[...slug]]/route.ts
import { createFetchHandler } from "@narudom96/nelysia/runtime-fetch"
const handler = createFetchHandler(app)
export const GET = (req: Request) => handler(req)
export const POST = (req: Request) => handler(req)

// SvelteKit — src/routes/api/nelysia/+server.ts
export const GET = ({ request }: { request: Request }) => fetchHandler(request)

// Astro — src/pages/api/nelysia.ts (direct export)
export const GET = createFetchHandler(app)
