## Version path: v0.6 ถึง v1.0

ก่อน v1.0 การเปลี่ยนแปลงต้องเป็น additive และ tag ที่ออกแล้วต้อง immutable

| Milestone | ขอบเขต | สถานะใน workspace | สถานะ public release |
| --- | --- | --- | --- |
| `v0.6` | strict types, context storage, lifecycle, metadata, typed DX และ modules | ผ่าน gate | historical `0.6.0` |
| `v0.7` | unified route metadata, provider architecture, auth และ typed API | ผ่าน gate | ยังไม่สร้าง milestone tag/release ใหม่ |
| `v0.8` | deterministic schema IR, generated validator/serializer และ compiler lanes | ผ่าน gate | ยังไม่สร้าง milestone tag/release ใหม่ |
| `v0.9` | production modules, CLI, package/deployment verification และ examples | ผ่าน gate | ยังไม่สร้าง milestone tag/release ใหม่ |
| `v1.0` | freeze routing, context, options, schema, auth, plugins, lifecycle, errors, server, inject และ client | public contract frozen | `v1.0.0` released |

ดังนั้น package ที่ผู้ใช้ติดตั้งจาก release ปัจจุบันคือ `v1.0.0` และ contract ที่
อธิบายในเอกสารนี้คือ contract ที่ freeze สำหรับสาย `1.x`

## Public contract ที่จะ freeze

### 1. Routing

รองรับ HTTP methods, static path, `:param`, wildcard, trailing slash, 404, 405,
HEAD และ OPTIONS โดย explicit `.options()` มี precedence เหนือ automatic `204`

```ts
import { Nelysia } from "@narudom96/nelysia"

const app = new Nelysia()
  .get("/users/:id", ({ params }) => ({ id: params.id }))
  .get("/assets/*", ({ params }) => ({ file: params["*"] }))
  .options("/users/:id", () => new Response(null, { status: 204 }))
```

การ chain เป็นวิธีที่แนะนำเพื่อรักษา type inference; การ register หลาย statement
ยังทำงานตามปกติ

### 2. Context และ lifecycle

`context.store` เป็นพื้นที่ request-local สำหรับข้อมูลที่แชร์ระหว่าง hooks และ
handler ส่วน `decorate()` ใช้สำหรับ service/capability ที่ผูกกับ application

```ts
const app = new Nelysia()
  .state("requestStarted", 0)
  .decorate("users", { find: async (id: string) => ({ id }) })
  .derive(({ store }) => ({ startedAt: store.requestStarted }))
  .get("/users/:id", async ({ users, params, startedAt }) => ({
    user: await users.find(params.id),
    startedAt
  }))
```

ขอบเขต hook ที่ freeze:

- `local` — เฉพาะ route/module ที่ประกาศ
- `scoped` — subtree ที่ถูกครอบด้วย group/mount
- `global` — ทุก route ใน application

`.derive()` และ `.resolve()` รองรับทั้ง sync และ async; `.lazy()`, `.mountLazy()`
และ `.use(Promise)` ใช้โหลด module แบบ deferred โดยยังคง API เดิม

### 3. Route options และ metadata

route/group/application ใช้ metadata รูปแบบเดียวกัน โดย inheritance คือ
application → parent group → child group → route; ค่าที่ใกล้ที่สุดชนะ และ object
merge แบบ shallow

```ts
const app = new Nelysia({
  routeOptions: { timeout: 10_000, rateLimit: "100/min" }
})
  .group("/api", (api) => api.post("/orders/:id", handler, {
    auth: { strategy: "jwt", role: "user" },
    body: OrderInput,
    response: { 201: Order, 400: BadRequest, 401: Unauthorized },
    rateLimit: "20/min",
    timeout: 5_000,
    cache: true
  }))
```

array/permissions ที่ประกาศใหม่จะแทนค่าเดิม; `false` ใช้ปิด feature ที่ inherited
และไม่มี implicit feature activation ถ้า plugin/provider ไม่ได้เปิดใช้

### 4. Schema และ validation

built-in schema ที่ deterministic สามารถเข้า generated validator/serializer ได้:

- primitive: string, number, integer, boolean, null
- object properties และ required
- array, items และ tuple
- enum, const, anyOf, allOf
- min/max, length, pattern และ date-time

Standard Schema, transform, custom runtime behavior, native `Response`, stream และ
custom serializer ที่พิสูจน์ไม่ได้จะ fallback ไป generic path โดยอัตโนมัติ ไม่เพิ่ม
query/body coercion ใหม่ และยังรักษา output shape, safe object keys และ status `400`

### 5. Authentication และ authorization

JWT ใช้ HS256 เท่านั้นและตรวจ header/segments/base64url/JSON/signature, `exp`, `nbf`,
issuer และ audience แบบ strict

```ts
import { jwt } from "@narudom96/nelysia/jwt"

type Claims = { sub: string; role: "user" | "admin" }

const app = new Nelysia()
  .use(jwt<Claims>({ secret: process.env.JWT_SECRET! }))
  .get("/public", () => "ok")
  .get("/me", ({ auth }) => ({ subject: auth.sub }), {
    auth: { strategy: "jwt", role: "user" }
  })
```

กติกาที่ freeze:

- `auth: "jwt"` และ `auth: "session"` เป็น required authentication
- `auth: "optional"` ใช้ได้เมื่อมี provider เดียวที่ active
- ไม่มี credential เป็น `401`; credential ผิดก็เป็น `401` ไม่เปลี่ยนเป็น anonymous
- role ไม่ผ่านเป็น `403`; roles ใช้ OR และ permissions ใช้ AND
- authentication และ authorization ใช้ AND semantics
- public route ไม่อ่าน `Authorization`, ไม่ verify token และไม่สร้าง auth payload
- `jwt<Claims>()`, `JwtPluginInstance<Claims>` และ `ctx.auth` narrow ตาม route
- `ctx.jwt` เป็น lazy/non-enumerable และ reuse `CryptoKey` ต่อ plugin instance

`AuthStrategyRegistry` รองรับ module augmentation; boolean และ legacy string ยังคง
ไว้เพื่อ compatibility แต่มี deprecation notice

### 6. Plugins และ providers

plugin ที่รองรับคือ function, Nelysia instance, `Promise<Nelysia>` และ lazy module
feature เช่น auth, rate limit, cache และ timeout ต้องลงทะเบียน provider ก่อนใช้ใน
route หาก provider ขาดต้อง fail ตอน registration พร้อม method, path และ feature

route ที่ไม่ใช้ feature จะไม่สร้าง guard, timer, parser หรือ allocation ของ feature
นั้นเพิ่ม

### 7. Response และ errors

ยังรองรับ positional form เดิม และเพิ่ม body-first form:

```ts
app.get("/created", ({ response }) =>
  response({ id: "ord_1" }, { status: 201, headers: { "x-source": "api" } })
)

app.get("/missing", () => {
  throw error(404, { code: "ORDER_NOT_FOUND" })
})
```

native `Response` และ `ReadableStream` ส่งต่อโดยไม่ execute handler ซ้ำ; error path
ใช้ `HttpError`, `error(status, body)` และ `onError` ตามลำดับ lifecycle

### 8. Server และ runtime

`listen()` ให้ `ServerInfo` ที่มีข้อมูลเดิมและ `NelysiaServer`/`stop()` แบบ additive
โดยไม่เปลี่ยน behavior ของ Bun และ Node

```ts
const server = app.listen(3000)
// ...
await server.stop()
```

Fetch adapter เดียวกันใช้กับ Deno, Cloudflare Workers, Vercel และ full-stack
framework fixtures; ข้อจำกัดของแต่ละ platform อยู่ใน [`compatibility.md`](./compatibility.md)

### 9. Typed inject และ client

```ts
const response = await app.injectTyped({
  method: "GET",
  path: "/users/:id",
  params: { id: "42" }
})

const client = createClient<typeof app>("http://localhost:3000")
const result = await client.users({ id: "42" }).get()
```

`inject()` มี route-aware overload เพิ่มจาก `injectTyped()` และ `injectUntyped()`;
สามารถ infer path params, body, query, headers, status-specific response และ typed
errors ได้ `createTypedClient<RouteMap>()` ยังคงอยู่เพื่อ compatibility

### 10. Compiler execution lanes

ชื่อ lane ที่เป็น public คือ:

| Lane | ใช้เมื่อ | พฤติกรรม |
| --- | --- | --- |
| `COMPILED` | semantics และ schema พิสูจน์ได้ | generated/standalone หรือ adapter fast path |
| `SPECIALIZED` | optimize ได้บางส่วนแต่ยังต้องใช้ runtime contract | params/static/schema/auth fast path |
| `GENERIC` | custom/opaque behavior หรือพิสูจน์ไม่ได้ | ใช้ reference runtime ที่ครบ semantics |

`static-prebuilt`, `static-sync`, generated validator และ params fast path เป็น
internal diagnostics/subtiers เท่านั้น ไม่ใช่ public API tier

ตรวจผลได้ด้วย:

```bash
npm run inspect -- ./src/app.ts
npm run routes
npm run package:build
```

อ่าน `dist/manifest.json` เพื่อดู route, lane, generation mode และ diagnostics
เช่น `NELY101`–`NELY111`; fallback ต้องระบุ route, field และเหตุผลเสมอ

## Production modules

ทุก module เป็น opt-in และไม่มี overhead เมื่อไม่ได้เปิดใช้

| Module | หน้าที่ | Failure/security contract |
| --- | --- | --- |
| `upload` | multipart และ storage adapter | จำกัด size/count/fields และ cleanup เมื่อ storage fail |
| `logger` | typed structured request logging | levels `debug/info/warn/error`, sink กำหนดเอง และ redact secret โดย default |
| `timeout` | deadline และ `AbortSignal` | default `504`, clear timer ทุก path; ไม่หยุด synchronous JS ที่กำลังทำงาน |
| `session` | session cookie/store | typed store contract และ provider registration |
| `roles` | role/permission checks | deny by default และ typed `require()` |
| `csrf` | CSRF token/header protection | reject unsafe request และกำหนด safe methods ได้ |
| `cache` | cache และ ETag/304 | fallback ไป origin และจำกัด TTL/entries |
| `health` | liveness/readiness | แยก check status และรายงาน failure ของ dependency |

ตัวอย่าง import:

```ts
import { upload } from "@narudom96/nelysia/upload"
import { logger } from "@narudom96/nelysia/logger"
import { timeout } from "@narudom96/nelysia/timeout"
import { session } from "@narudom96/nelysia/session"
import { roles } from "@narudom96/nelysia/roles"
import { csrf } from "@narudom96/nelysia/csrf"
import { cache } from "@narudom96/nelysia/cache"
import { health } from "@narudom96/nelysia/health"
```

export ทั้งหมด 25 รายการและประเภทของแต่ละ export ดูได้ใน [Package Export Matrix](./index.html#exports)

## Release gates และหลักฐาน

คำสั่งรวมของแต่ละ milestone:

```bash
npm run release:check:v06
npm run release:check:v07
npm run release:check:v08
npm run release:check:v09
npm run release:check:v1
```

gate ครอบคลุม typecheck, Node/Bun tests, negative type tests, compiler parity,
JWT matrix, module failure tests, package build/imports, deployment/framework smoke,
docs check, security audit, short performance matrix, runtime fuzz, memory burst และ
soak 1M/10M

กติกา benchmark v1.0:

- warmup 2–3 วินาที แยกจาก measurement
- 5–10 วินาทีต่อ sample และ 3–5 รอบ
- route counts 1/10/100/500 และ workload static/params/query/body/schema/JWT/hooks/combined
- รายงาน median, min/max, p95/p99, failures, CPU, RSS, heap และ environment
- regression ≤2% ผ่าน; 2–5% ต้อง investigate; >5% หรือ unexplained regression block release
- ต้องตรวจทั้ง `app.inject()` และ `listen(0) → fetch()`

หลักฐานล่าสุดอยู่ที่ [benchmark index](./benchmark-results.html),
[short v1.0 evidence](./benchmark-short-v1-2026-09-15.md),
[runtime contract](./benchmark-runtime-contract-2026-09-15.md) และ
[1M/10M soak report](./soak-roadmap-rerun-2026-09-15.md)

`30m`, `1h`, `6h` และ `24h` เป็น future evidence; 24-hour soak ยังไม่ถูกรันและ
ไม่ควรใช้เอกสารนี้ประกาศ production readiness

## Compatibility และ deprecation policy

- ก่อน v1.0 เพิ่ม API แบบ additive และคง API เดิมไว้
- legacy auth string/boolean และ compatibility aliases มี deprecation notice ก่อนลบ
- ไม่มี automatic query/body coercion เพิ่ม
- provider ที่ขาด fail ตอน registration ไม่ fallback เงียบ
- compiler ที่พิสูจน์ semantics ไม่ได้ fallback generic
- หลัง v1.0: `1.0.x` แก้ bug/security, ความสามารถใหม่แบบ additive อยู่ใน `1.x`, breaking change ไป `2.0`

## หลังการ release v1.0

เอกสาร, workspace contract และ public release พร้อมแล้ว ส่วนการ publish npm และ
หลักฐานระยะยาวเป็น operation แยกต่างหาก:

1. ตรวจ tarball/imports จาก release จริง
2. publish npm เมื่อ registry account พร้อม
3. ถ้าจะประกาศ production readiness ให้รันและแนบหลักฐาน long-running soak ที่อนุมัติแล้ว

สถานะปัจจุบันคือ **Nelysia v1.0.0 released**; production readiness ยังไม่ถูก
ประกาศเพราะ 24-hour soak ถูก deferred
